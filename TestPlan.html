Role-Based Test Cases

1. SaaSAdmin (Platform Admin) Test Cases

TC-SA-01: Global Platform Rollup & Multi-Region Revenue Analytics SaaSAdmin
Entry Point: /saasadmin
Policy Required: SaaSAdmin
Prerequisites: Signed in as admin@boxdropaz.com
Execution Steps:
  1. Navigate to /saasadmin after signing in as SaaSAdmin.
  2. Verify that the platform overview displays total revenue figures for the current month and previous month.
  3. Check the Region Rollup table listing active regions (e.g., Phoenix, Tucson).
  4. Validate active subscriber counts, monthly recurring revenue (MRR), and outstanding gift credit totals.
  5. Ensure the 12-month revenue chart renders properly across all regions.
Expected Result: System renders global financial metrics, aggregate active rental counts, active subscription metrics, and regional break-downs without throwing HTTP 403 or missing region data.
TC-SA-02: Region Management - Create New Region with Delivery Zones SaaSAdmin
Entry Point: /saasadmin/regions/new
Policy Required: SaaSAdmin
Prerequisites: Admin session active
Execution Steps:
  1. Navigate to /saasadmin/regions/new.
  2. Fill in Name (e.g., "Tucson Market"), Slug ("tucson"), Time Zone ("US/Arizona"), Support Phone.
  3. Add delivery zones: Zone A (Surcharge $0, Zip Codes: 85701, 85702), Zone B (Surcharge $25, Zip Codes: 85710, 85711).
  4. Configure default damage fees: Crate Replacement ($40.00), Dolly Replacement ($95.00), Missed Pickup ($25.00), Deep Clean ($3.00).
  5. Click Save Region.
Expected Result: Region record and delivery zones are persisted in DynamoDB. User is redirected to package configuration for the new region with a success notification.
TC-SA-03: Package Catalog Management - Add & Edit Crate Bundles SaaSAdmin
Entry Point: /saasadmin/packages
Policy Required: SaaSAdmin
Prerequisites: Existing region selected
Execution Steps:
  1. Select a region from the packages drop-down menu.
  2. Click New Package.
  3. Enter Name: "Mega Mansion Bundle", Crate Count: 120, Dolly Count: 5, Base Price: $349.00, Extra Week Price: $175.00.
  4. Save package and verify it appears in the active catalog listing.
  5. Toggle the package status to "Inactive" and verify it is hidden from the public booking wizard.
Expected Result: Package pricing is updated dynamically in DynamoDB. Inactive packages are hidden from D2C booking flows immediately.
TC-SA-04: Global User Management & Privileged Role Assignment SaaSAdmin
Entry Point: /admin/users
Policy Required: SaaSAdmin
Prerequisites: SaaSAdmin session active
Execution Steps:
  1. Navigate to User Management at /admin/users.
  2. Search for a registered user by email or name.
  3. Change the user's role to RegionalAdmin or Worker.
  4. Assign or update the user's primary assigned RegionId.
  5. Toggle "Disable Account" on a test user and verify they cannot sign in at /account/login.
Expected Result: Role changes take effect immediately in Identity stores. Disabled users receive a clean "account disabled" error upon login attempts.
TC-SA-05: Stripe Event Store Audit & Webhook Diagnostics SaaSAdmin
Entry Point: /saasadmin/stripe-events
Policy Required: SaaSAdmin
Prerequisites: Webhooks received or local CLI forwarding enabled
Execution Steps:
  1. Open /saasadmin/stripe-events.
  2. Filter by Event Type (e.g., checkout.session.completed, invoice.paid).
  3. Filter by Outcome ("Failed", "Unprocessed", "Success").
  4. Verify raw payload details, timestamp, and error messages if signature validation or processing fails.
Expected Result: Full log of received Stripe webhooks is rendered with filter capabilities and status indicators.

2. RegionalAdmin (Market Operator) Test Cases

TC-RA-01: Regional Dashboard Overview & Market Scope Verification RegionalAdmin
Entry Point: /admin
Policy Required: AnyAdmin
Prerequisites: Signed in as phoenix.admin@boxdropaz.com
Execution Steps:
  1. Log in as RegionalAdmin.
  2. Verify that the dashboard automatically scopes all metrics to Phoenix.
  3. Check active rentals count, crates currently in the field, upcoming deliveries, and pending damage charges.
  4. Attempt to manually append ?region=other-region-id to the URL.
Expected Result: RegionalAdmin is strictly restricted to their assigned region. Appending external region query parameters is ignored and pinned back to their home region.
TC-RA-02: Inventory Stock Totals & Automated Shortage Recalculation RegionalAdmin
Entry Point: /admin/inventory
Policy Required: AnyAdmin
Prerequisites: RegionalAdmin session
Execution Steps:
  1. Navigate to /admin/inventory.
  2. Inspect current counts for Total Totes, Custom-fit Dollies, Index Card Packs, and Card Holder Packs.
  3. Update total physical tote stock (e.g., from 500 to 450).
  4. Submit form and verify future booking availability is reconciled against physical asset capacity.
Expected Result: Inventory totals update in DynamoDB, and any predicted future asset shortages automatically generate open restock tasks.
TC-RA-03: Delivery & Pickup Scheduling & Blackout Date Rules RegionalAdmin
Entry Point: /admin/schedule
Policy Required: AnyAdmin
Prerequisites: RegionalAdmin session
Execution Steps:
  1. Open /admin/schedule.
  2. Set Minimum Notice Days (e.g., 2 days).
  3. Select active delivery windows for Weekdays (e.g., 8am-12pm, 12pm-4pm) and Weekends.
  4. Add a Blackout Date for an upcoming holiday (e.g., Christmas Day - All Day).
  5. Go to public booking wizard and verify that the blacked-out date cannot be selected for delivery or pickup.
Expected Result: Blackout dates and window availability rules are immediately reflected in public customer scheduling calendars.
TC-RA-04: Order Management, Status Overrides & Internal Notes RegionalAdmin
Entry Point: /admin/orders
Policy Required: AnyAdmin
Prerequisites: Active orders present
Execution Steps:
  1. Open /admin/orders and search for an order by Order Number or Customer Name.
  2. Click on an order to view full details at /admin/orders/{id}.
  3. Add an internal staff note ("Customer requested gate code 1234").
  4. Override order status (e.g., set status from "Confirmed" to "Out For Delivery").
  5. Verify the status badge updates and the change is logged with author name and timestamp.
Expected Result: Order updates save properly and audit notes maintain a complete history of administrative actions.
TC-RA-05: Damage Fee Review, Stripe Card Charging & Waiving RegionalAdmin
Entry Point: /admin/orders/{id}
Policy Required: AnyAdmin
Prerequisites: Order with reported damage line items
Execution Steps:
  1. Locate an order with pending damage items reported by a worker (e.g., 2 missing crates @ $40 each = $80).
  2. Review the damage description and reported photo/note.
  3. Test Action A: Select line item and click Approve & Charge Card. Verify Stripe PaymentIntent is triggered against card on file.
  4. Test Action B: On another line item, click Waive Fee and enter a reason ("Curtsied fee as courtesy").
Expected Result: Approved charges attempt payment against stored payment method via Stripe API. Waived fees update status to "Waived" without touching customer card.
TC-RA-06: Regional User Impersonation & Security Boundary Check RegionalAdmin
Entry Point: /admin/users
Policy Required: AnyAdmin
Prerequisites: Users in region
Execution Steps:
  1. Navigate to /admin/users.
  2. Locate a Customer or Realtor user in Phoenix.
  3. Click Impersonate User. Verify header banner displays "Impersonating [User Email]" with a "Stop Impersonation" button.
  4. Attempt to impersonate another RegionalAdmin or SaaSAdmin account.
  5. Click Stop Impersonation and verify returning seamlessly to original RegionalAdmin account.
Expected Result: RegionalAdmin can impersonate non-admin users in their region. System rejects attempting to impersonate peer admins or platform admins.

3. Worker (Delivery Driver) Test Cases

TC-WK-01: Daily Mobile Manifest Inspection & Stop Grouping Worker
Entry Point: /worker
Policy Required: Fulfillment
Prerequisites: Signed in as worker@boxdropaz.com
Execution Steps:
  1. Log in as Worker on a mobile browser or viewport.
  2. Verify today's manifest displays separate tabs or cards for Deliveries and Pickups.
  3. Ensure stops are sorted logically by time window (e.g. 8am-12pm) and ZIP code.
  4. Check that unpaid or cancelled orders do NOT appear on the driving manifest.
Expected Result: Clean, one-handed mobile interface listing confirmed deliveries and active pickups for the selected manifest date.
TC-WK-02: Delivery Completion & Index Card Consumable Deduction Worker
Entry Point: /worker/order/{id}?pickup=false
Policy Required: Fulfillment
Prerequisites: Unfulfilled delivery scheduled for today
Execution Steps:
  1. Open a scheduled delivery stop on the manifest.
  2. Verify order summary details: Customer Name, Delivery Address, Tote Count, Dolly Count, Index Cards required.
  3. Click Mark Delivered.
  4. Verify that inventory deducts 1 pack of 300 color-coded index cards from regional stock.
  5. Verify order status transitions to Delivered and sets DeliveredAtUtc timestamp.
Expected Result: Order is marked delivered, delivery timestamp is saved, and index card consumables stock is decremented cleanly.
TC-WK-03: Pickup Collection & Asset Shortage Auto-Queuing Worker
Entry Point: /worker/order/{id}?pickup=true
Policy Required: Fulfillment
Prerequisites: Order out for pickup
Execution Steps:
  1. Open a scheduled pickup stop.
  2. Enter returned asset quantities: Expected 50 crates / 2 dollies; Driver inputs 48 crates / 2 dollies returned.
  3. Click Mark Picked Up.
  4. Verify order status transitions to Completed.
  5. Inspect admin area for the order to confirm that 2 missing crates ($80 total) were automatically added as a pending damage line item for admin review.
Expected Result: Pickup is recorded, inventory reflects returned counts, and short counts auto-create pending damage charges without charging the customer immediately.
TC-WK-04: On-Site Damage Reporting (Deep Clean / Damaged Equipment) Worker
Entry Point: /worker/order/{id}/report
Policy Required: Fulfillment
Prerequisites: Active pickup stop open
Execution Steps:
  1. On a pickup order screen, select Report Damage / Cleaning Fee.
  2. Choose Damage Kind: "Deep Clean Required". Enter Quantity: 5 crates. Description: "Heavy oil/paint residue inside totes".
  3. Submit report.
  4. Verify driver sees confirmation alert that report was queued for admin review.
Expected Result: Damage report is stored under the order with unit calculation ($3/crate x 5 = $15) pending admin authorization.
TC-WK-05: Restock Task Fulfillment & Usable Stock Addition Worker
Entry Point: /worker (Restock section)
Policy Required: Fulfillment
Prerequisites: Open restock task present
Execution Steps:
  1. Locate an open inventory restock task on the worker manifest.
  2. Enter received equipment: 50 new totes, 50 card holder label clips, 2 dollies, 5 index card packs.
  3. Click Complete Restock Task.
Expected Result: System verifies totes are paired with label holder clips before adding to usable tote stock. Restock task is closed.
